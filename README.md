# agropipeline.ru — лендинг с формой заявки

Статическая страница (Jinja2 + CSS + минимум JS) и эндпойнт приёма заявок для
холодных звонков поставщикам СЗР и удобрений. Собрана по ТЗ как отдельный
репозиторий, устроена как будущая папка `landing/` внутри `rngoblin/agropipe` —
переносится туда одним шагом (см. «Деплой» ниже).

## Структура

```
landing/
  content.yaml            – все тексты страницы (правь только этот файл)
  templates/
    index.html.j2         – разметка главной страницы
    privacy.html.j2        – страница политики (текст-заглушка)
  static/
    css/landing.css       – единственный файл стилей
    js/form.js            – валидация и отправка формы (72 строки)
    fonts/                – IBM Plex Sans/Mono, woff2, кириллица+латиница
    img/sample-report.*    – фрагмент заключения (СЕЙЧАС ПЛЕЙСХОЛДЕР)
  api/lead.py              – роуты GET /, GET /privacy, POST /api/lead
  dev_server.py            – локальный запуск без остального проекта agropipe
```

## Как менять тексты

Все формулировки страницы — в [`landing/content.yaml`](landing/content.yaml).
Разметка их не содержит, поэтому правка текста не требует трогать
`index.html.j2`. Реквизиты исполнителя (`meta.executor_inn`, `executor_city`,
`executor_since`, `phone_display`, `phone_href`, `email`) сейчас — плейсхолдеры:
этих данных не было ни в ТЗ, ни в репозитории `agropipe`, вписать перед
публикацией.

## Как запустить локально

Нужен Python 3.12 (та же версия, что в `agropipe/.venv`) и зависимости:

```bash
python3.12 -m venv .venv
.venv/bin/pip install fastapi==0.141.1 starlette==1.6.0 uvicorn==0.52.4 \
  Jinja2==3.1.6 pyyaml python-multipart
```

Версии продублированы из `requirements.txt` репозитория `agropipe` — после
переноса `landing/` туда отдельно ставить ничего не нужно, кроме
`python-multipart` (см. «Деплой», пункт 2).

Запуск:

```bash
cd landing
../.venv/bin/python3 dev_server.py
```

Открыть `http://127.0.0.1:8080/`. Заявки в этом режиме падают в
`landing/cases/_leads/` (создаётся автоматически), уведомление владельцу не
уходит — `intake.py` недоступен вне репозитория agropipe, вместо отправки
пишется строка в консоль.

Проверено вручную: мобильная раскладка без горизонтальной прокрутки, маска
телефона, happy path, honeypot, отправка раньше 3 секунд, лимит 5 заявок/час
с IP, ошибки валидации (JS и без JS — обычным POST с рендером той же
разметки), фокус клавиатурой на каждом интерактивном элементе.

## Деплой на Timeweb (перенос в agropipe)

1. Скопировать папку `landing/` целиком в корень репозитория `agropipe` на
   сервере (`rsync` или `git subtree`, решите сами — это разные репозитории,
   общей истории коммитов нет).

2. Добавить в `requirements.txt` agropipe одну строку:
   ```
   python-multipart==0.0.20
   ```
   (или актуальную версию — это единственная новая зависимость; fastapi,
   starlette, Jinja2, PyYAML в проекте уже есть).

3. В `bot.py` agropipe, рядом с объявлением `app = FastAPI(...)`, добавить:
   ```python
   from fastapi.staticfiles import StaticFiles
   from api.lead import router as lead_router

   app.mount("/static", StaticFiles(directory="landing/static"), name="landing-static")
   app.include_router(lead_router)
   ```
   Роуты `GET /`, `GET /privacy`, `POST /api/lead` из `api/lead.py` начнут
   обслуживаться тем же процессом (`127.0.0.1:8000`), что и вебхук бота —
   как требует раздел 7 ТЗ.

4. Добавить в nginx-конфиг сервера (рядом с существующим `/webhook`, см.
   `deploy/agropipe-nginx-webhook.conf`) location для корня сайта, если её
   ещё нет — `agropipeline.ru` должен проксироваться на тот же
   `127.0.0.1:8000`, что и бот.

5. Переменные окружения (в `.env` agropipe уже есть `MAX_BOT_TOKEN` и
   `OWNER_USER_ID` — `notify_owner()` в `api/lead.py` использует их
   напрямую, отдельно настраивать не нужно). По желанию — `LEADS_DIR`, если
   заявки должны лежать не в `cases/_leads/` относительно рабочей директории
   процесса, а по другому пути.

6. **Обязательно до запуска в прод:**
   - заменить `landing/static/img/sample-report.png` и `.webp` на настоящий
     (обезличенный) скриншот фрагмента PDF-заключения — текущие файлы это
     явно помеченный водяным знаком макет, не настоящие данные;
   - заполнить реквизиты в `content.yaml` (ИНН, город, телефон, почта, год
     основания);
   - добавить рядом со шрифтами файл лицензии SIL Open Font License 1.1
     (IBM Plex распространяется по ней) — текст см.
     https://scripts.sil.org/cms/scripts/page.php?site_id=nrsi&id=OFL ;
   - согласовать с юристом текст `privacy.html.j2` — сейчас это заглушка.

## Куда падают заявки

`POST /api/lead` пишет каждую валидную заявку атомарно (`write` во временный
файл + `rename`) в `LEADS_DIR` (по умолчанию `cases/_leads/` относительно
рабочей директории процесса — на проде это будет `agropipe/cases/_leads/`,
рядом с обычными кейсами конвейера, но в своей подпапке). Формат файла:

```json
{
  "id": "2026-09-10T11-09-38_95abad42",
  "status": "new",
  "created_at": 1789020578.62,
  "ip": "203.0.113.1",
  "name": "...",
  "phone": "+79995551122",
  "company": "..."
}
```

Владелец получает уведомление тем же каналом, что уведомления о падении
бота, — прямым сообщением от `intake.MaxAPI` в MAX (см. `notify_failure.py`
в agropipe для образца этого же механизма).

Заявки с непустым honeypot-полем, отправленные быстрее 3 секунд после
отрисовки формы, или превышающие 5 заявок в час с одного IP, — не
сохраняются и не уведомляются, но пользователь видит тот же экран успеха
(раздел 7 ТЗ, честный вид для бота — тихий отказ без подсказок, что его
раскрыли).

## Известные ограничения (заполнить перед публикацией)

- `sample-report.png`/`.webp` — макет с водяным знаком, не настоящее
  заключение.
- Реквизиты исполнителя в `content.yaml` — плейсхолдеры.
- `privacy.html.j2` — текст-заглушка, нужен юридический текст.
- Домен `agropipeline.ru` уже делегирован на сервер Timeweb (проверено:
  NS timeweb.ru/timeweb.org, A-запись резолвится) — сама страница на него
  пока не задеплоена, только подготовлена.
